# Baseline: icon + title vs Proposed: text cloud

탭 라벨 방식(IV1)과 탭 폭(IV2)에 따라, 사용자가 원하는 탭 하나를 다시 찾는 데 걸리는 시간을 재는 시뮬레이터입니다.

> 이 폴더에는 버전 설정이 담긴 `index.html`만 있고, 코드는 `../common/`을 함께 씁니다. 다른 버전(text_LLM, text_title_LLM), 엑셀 연결, description 단서는 `../README.md`를 보세요.

| | 수준 |
|---|---|
| **IV1 라벨 방식** | **Baseline** = arXiv 아이콘 + 제목(기본) 또는 랜덤 DOI / **Proposed** = **아이콘 없이** 본문 빈도 Top-1 단어 (text cloud) |
| **IV2 탭 폭** | narrow / middle / wide. 기본 40 / 80 / 160px, 설정에서 변경 가능. 탭 수는 고정 |
| **세션 구성** | **읽기 단계**(선택한 아티클을 하나씩) → 2 × 3 = 6 조건 × 조건당 N 시행 |
| **아티클 수** | **10 / 20 / 30** 중에서 선택. 폴더 PDF를 파일명 순으로 정렬한 앞에서부터 사용 |
| **기본값** | 아티클 **10**개 · 조건당 시행 **10**회 (6 × 10 = 60 시행, 아티클마다 정답 6회) · 시행당 탭 **10**개 (매 시행 아티클 전체가 탭으로 열림) |
| **조건당 시행 수 N** | 6N이 아티클 수로 나누어떨어지는 값만 고를 수 있음 → **모든 아티클이 정답으로 정확히 같은 횟수** (예: 30개·N=5 → 각 1회, 10개·N=10 → 각 6회) |
| **순서 균형** | 6 조건의 순서는 balanced Latin square(Williams)로 정함. 참가자 번호로 행을 고름 |

## 실행

`index.html`을 Chrome 또는 Edge로 열면 됩니다(설치 불필요, pdf.js를 CDN에서 받으므로 인터넷 필요). 실험 중에는 **F11 전체화면**을 쓰세요.
`python -m http.server`로 열어도 됩니다.

## 준비

1. **설정 열기**: ⚙(왼쪽 아래) 또는 `Ctrl+Shift+S`.
2. **📁 폴더 선택**: PDF 30개가 들어 있는 폴더를 고릅니다.
   - 폴더 바로 아래의 `*.pdf`를 모두 읽습니다.
   - 처음 한 번은 텍스트를 추출하느라 시간이 걸리고, 이후에는 캐시를 씁니다.
   - 다음에 열 때는 "이전 폴더 다시 연결"만 누르면 됩니다.
   - 같은 폴더에 `cues.csv`(열: `filename,cue`)를 두면 과제 단서로 사용합니다.
3. **참가자 ID**: `P03`처럼 숫자를 포함해 입력합니다. 이 숫자로 Latin square 행이 정해지며, 블록 순서는 표에서 확인할 수 있습니다.
4. **실험 화면으로 ▶**

## 읽기 단계 (세션 시작)

1. 흐린 화면에 "읽기 단계 0 / 30"과 **읽기 시작** 버튼이 표시됩니다.
2. 탭 하나에 아티클이 하나씩 열립니다.
   - 탭 이름은 "아티클 i / 30"이며, Baseline 라벨이나 Proposed 라벨은 보여주지 않습니다(조건 중립).
   - 읽는 순서는 기본적으로 참가자마다 랜덤입니다.
3. 원하는 만큼 읽은 뒤 과제박스의 **다음 ▶**을 누릅니다.
   - 아티클당 최소 읽기 시간은 기본 0초(바로 넘어갈 수 있음)입니다. 설정에서 30초 등으로 바꾸면 그 시간이 지나야 버튼이 활성화되고, 과제박스에 남은 초가 표시됩니다.
4. 30개를 모두 읽으면 실험(블록 1)이 시작됩니다.
5. 새로고침하면 읽던 위치부터 "이어서 읽기"가 됩니다.
6. 아티클별 읽은 시간은 **읽기 기록 CSV**로 받을 수 있습니다. 컬럼은 `participant_id, read_order, file, read_s, min_s, start_iso, end_iso`입니다.

## 한 시행의 흐름

1. **흐린 화면**: "블록 b / 6"과 "n / 8"이 표시되고, 블록의 첫 시행이면 **Start**, 이후에는 **Next** 버튼이 나옵니다.
2. 버튼을 누르면 이번 시행의 PDF 5개가 **셔플된 순서로 탭에 열리고**, 첫 탭이 표시됩니다.
3. **탐색 단계**: 참가자가 모든 탭을 한 번씩 눌러 확인해야 과제박스의 **Start**가 활성화됩니다. 과제박스에 진행 상황이 (3 / 5)처럼 표시됩니다.
4. **Start**: 과제박스에 찾을 탭의 단서가 나타나고, **60초 카운트다운**이 시작됩니다.

   | 상황 | 결과 |
   |---|---|
   | 정답 탭 클릭 | 성공, 종료 |
   | 다른 탭 클릭 | Errors +1, 타이머 계속 (이미 보고 있는 탭을 다시 누르는 것은 제외) |
   | 60초 경과 | `timeout`, 실패 |
   | **Missing** | `missing`, 포기 |

5. 다시 흐린 화면으로 돌아갑니다. 48 시행이 끝나면 "완료"가 표시됩니다.

진행 상황은 기록 기준이라, 새로고침해도 이어서 진행됩니다.

## 아티클 배정

1. **아티클 풀**: 폴더 PDF를 파일명 순(숫자 인식: 1, 2, …, 10)으로 정렬한 앞의 10, 20 또는 30개를 씁니다. 읽기 단계도 이 아티클만 읽습니다.
2. **N 후보**: 6N이 아티클 수로 나누어떨어지는 N을 작은 것부터 10개 보여줍니다.
   - 10개 또는 30개: N = 5, 10, …, 50
   - 20개: N = 10, 20, …, 100
3. **정답 순서**: 아티클 전체를 셔플한 묶음을 (총 시행 ÷ 아티클 수)번 이어 붙여 만듭니다. 그래서 모든 아티클이 정답으로 정확히 같은 횟수 나오고, 같은 정답이 연달아 나오지 않습니다.
4. **시행의 탭**: 정답과, 지금까지 탭으로 덜 나온 나머지 아티클(탭 수 − 1)개로 채웁니다. 탭 수를 아티클 수와 같게 하면 매 시행 모든 아티클이 탭으로 열립니다.
5. **시드**: 배정은 시드로 고정되어 모든 참가자가 동일합니다. 조건 순서만 Latin square로 바뀌므로, 같은 정답이 참가자마다 다른 조건에 놓입니다.

## 탭 폭 → 보이는 정보 (Chromium 수치 기반)

설정값은 화면상 탭 폭입니다. 내부 계산에서는 Chrome의 탭 겹침 18px, 안쪽 여백 20px, 파비콘 16px, 닫기 버튼 영역 20px을 반영합니다. 비활성 탭은 내용 폭이 68px 미만이면 닫기 버튼이 숨겨집니다.

| 폭 | Baseline 비활성 | Baseline 활성 | Proposed 비활성 (아이콘 없음) | Proposed 활성 |
|---|---|---|---|---|
| 40px | 아이콘만 | 닫기만 | 글자 18px (약 2자) | 닫기만 |
| 80px | 아이콘 + 글자 34px (약 5자) | 아이콘 + 14px + 닫기 | 글자 58px (약 8자) | 38px + 닫기 |
| 160px | 아이콘 + 글자 94px (약 14자) + 닫기 | 같음 | 글자 118px (약 17자) + 닫기 | 같음 |

탭 폭 × 탭 수가 창보다 넓으면 탭 줄을 **좌우로 스크롤**할 수 있습니다. 탭 줄 바로 아래에 얇은 스크롤바가 생기고(드래그·클릭 가능) 마우스 휠로도 좌우로 움직이며, 활성 탭은 항상 보이도록 자동으로 스크롤됩니다. 설정의 폭 표에는 `↔ 스크롤`로 표시됩니다.

## 설정 항목

설정 패널 오른쪽 위의 **↺ 모든 설정 기본으로** 버튼을 누르면 모든 설정이 기본값으로 돌아갑니다. 측정 기록, 읽기 기록, 불러온 PDF 폴더는 유지됩니다.

- **Baseline 라벨**: 제목(첫 페이지에서 추정, 기본) 또는 랜덤 DOI
  - 랜덤 DOI는 arXiv ID 형식(예: `2403.17219v1`)입니다.
  - 만드는 법: q = 상수 × 논문 번호(파일명의 첫 숫자, 예: `01.pdf` → 1), q³ + 1000003·q의 뒤쪽 자리를 잘라 연·월·일련번호·버전으로 씁니다.
  - 상수는 설정에서 바꿀 수 있습니다(6~10자리). 끝자리가 0이 아닌 복잡한 수일수록 고르게 섞입니다.
- **Baseline 아이콘**: 기본은 arXiv 로고 풍 아이콘입니다. PDF 폴더에 `baseline_icon.png`(.ico/.svg)를 두면 그 이미지를 대신 씁니다.
- **주소창**: 모든 조건에서 동일하게 `arxiv.org/pdf/<랜덤 ID>`를 표시합니다(빈 주소창, 숨김으로도 바꿀 수 있음).
- **과제 단서**
  - **엑셀 description (기본)**: 참가자 안에서 아티클별로 중복 없이 랜덤 배정
  - cues.csv
  - 논문 제목
  - 첫 페이지 미리보기
  - 없음 (진행자가 구두로 안내)
- **세션**: 조건당 시행 수, 시행당 탭 수, 제한 시간, 시드, Latin square 켬/끔
- **화면**: 주소창, 호버 카드
- **Proposed 키워드 규칙**: 불용어, References 이후 제외, 복수형 합치기, 수동 라벨

## 관리자 모드 (흐름 점검용)

설정 → 1. 참가자 · 세션 → **관리자 모드**를 켜면, 과제박스 아래에 `ADMIN` 표시와 **⏭ 넥스트 스텝** 버튼이 생깁니다.

| 단계 | 버튼 | 동작 |
|---|---|---|
| 읽기 | ⏭ 다음 아티클 | 최소 읽기 시간을 무시하고 다음 아티클로 넘어감 |
| 탐색 | ⏭ 탭 확인 완료 | 모든 탭을 확인한 것으로 처리하고 Start를 활성화 |
| 검색 (Start 후) | ⏭ 정답 처리 | 정답 탭을 클릭한 것으로 처리 (성공) |

- 관리자 버튼으로 처리한 시행과 읽기는 CSV의 `admin` 컬럼에 `1`로 표시되므로, 분석할 때 걸러내면 됩니다. 설정의 기록 표에도 `ADMIN` 표시가 붙습니다.
- 실제 참가자 실험 전에는 관리자 모드를 끄고, 점검하며 쌓인 기록은 "이 참가자 기록 삭제"로 지우세요.
